# Manual UI acceptance

Use only fictional figures. This checklist proves that the UI and agent path
produce the same canonical v4 editable document, and that a complete comparison
can be created, reviewed, exported, cleared, and restored without editing JSON.

## Editable coverage

| Area | User-created or editable through the UI |
| --- | --- |
| Comparison | Title, comparison currency, number format, income growth, expense inflation, projection years |
| Monthly fields | Label, description, category, per-option/shared use, shared amount, accuracy status, date, source, note |
| Each option | Name, location, income summary, status, country badge, household earners, option currency, conversion ratio/date/source, gross compensation and its evidence, colour |
| Each option's monthly inputs | Amount in either linked currency plus accuracy status, date, source, and note for every per-option field |
| Qualitative inputs | Spouse-income, childcare, transport, residence/visa, and bonus assumptions; benefits and uncertainties |
| Context and research | Excluded support name/amount/note; research topic, title, finding, scope, status, publisher, source title/link/date, and review note |

`kind`, schema version, stable IDs, and `updatedAt` are generated by the app.
Migration notes are read-only provenance created only when an older supported
file is converted; they are not a user assumption or financial input.

## Fresh setup

1. Open a clean browser origin and choose **Enter my details**. Confirm there
   are no options, research records, support entries, sources, or qualitative
   claims. The standard field definitions and neutral `unknown` evidence shells
   are structure, not user data.
2. Set the comparison currency, number format, income growth, expense inflation,
   and projection length yourself. Confirm these assumptions appear in the
   editable export and are not represented as agent-supplied or derived values.
3. Add, rename, and remove one field in each available category: deduction,
   automatic investment, living cost, commitment, and planned investment.
   Confirm shared commitments and shared planned investments ask for amounts in
   the comparison currency once, while every per-option field appears in every
   option's value and evidence maps. Confirm every shared amount starts blank
   and requires a typed value or the section's explicit **Use 0** action.
4. Enter a shared amount and confirm the comparison currency locks before any
   option exists. Set every shared and excluded-support amount back to zero and
   confirm it unlocks; no entered number may silently change currency.
   Open the restart prompt while an unsaved fictional amount is present, cancel,
   and confirm the same draft value returns. Repeat and download the draft backup
   before cancelling.
5. Expand **External Help / Family Support received**, add a fictional context
   note, and confirm the UI says it is excluded from every total.
6. Expand **Research and sources**, add a fictional official HTTPS source and
   user-authored finding, date, status, and scope. Choose which options it
   applies to.

## Option and currency entry

1. Add a comparison-currency current option. Confirm each amount has one input
   labelled as both the option and comparison currency, and its conversion ratio
   is exactly `1`. Confirm gross and every per-option monthly amount start blank;
   saving is blocked until each has an entered amount, an explicit `0`, or the
   section's **Use 0** confirmation.
2. Add a fictional non-comparison-currency option. Enter its currency, a
   strictly positive conversion ratio, a source, and an as-of date yourself.
   Confirm each is present in the editable export.
3. Enter gross pay in the `CAD` input and confirm the linked `USD` input changes.
4. Enter housing in the `USD` input and confirm the linked `CAD` input changes.
5. Repeat with a deduction, automatic investment, and any custom per-option
   commitment or planned investment.
6. Change the conversion ratio. Confirm stored local amounts do not move, linked
   comparison-currency amounts and calculated totals do, and shared
   comparison-currency amounts remain fixed.
7. Save, reopen the option, and confirm the linked inputs, preview, card, expanded
   calculation, and comparison table agree.
8. Attempt to save an otherwise complete non-comparison-currency option without
   each of currency, positive ratio, date, and source. Confirm the option is
   rejected as one invalid unit; no partial option is added or exported. Repeat
   after removing one linked per-option value and one linked evidence entry.

## Progressive disclosure and validation

1. Confirm a long category such as standard living costs is collapsed initially
   and its summary shows the item count and entered total.
2. Confirm short required categories remain open.
3. Use Tab, Enter, and Space on every disclosure summary. Focus must be visible.
4. Clear a required value inside a collapsed section and submit. The section must
   open, the error summary must be announced, and focus must move to the field.
5. At widths of `320px` and `650px`, confirm linked currency inputs stack without
   horizontal page overflow and Save/Cancel remain reachable.

## Full round trip

1. Add user-authored qualitative assumptions, benefits, uncertainties,
   field-level evidence, and at least one source through the UI.
2. Confirm External Help / Family Support is visible as context on the dashboard
   but does not alter income, expenses, savings, charts, or rankings.
3. Download the editable comparison file and the family view. Validate the
   editable file with `npm run validate:data -- <file>`.
4. Normalize the editable v4 JSON by parsing it, replacing only `updatedAt` with
   one fixed token, and serializing object keys in a deterministic order. Keep
   every other field, including title, locale, field definitions, values,
   evidence, conversion details, assumptions, support, research, qualitative
   fields, and migration notes. Do not add calculated totals or projections.
5. Clear only this fictional browser dashboard, import the editable file, review
   the complete-replacement preview, and confirm it. Export again, normalize it
   the same way, and confirm exact equality with the pre-clear normalized file.
6. Confirm all inputs and totals before and after. Invalid imports, including a
   document with one option missing a linked field or a
   non-comparison-currency conversion component, must leave the existing
   dashboard unchanged.
7. Start removal of a populated field and of an option. Each confirmation must
   name the scope and offer a saved backup, Cancel, and a distinct final removal
   action. Cancel both operations and confirm nothing changed.
8. With a recognized older browser migration whose non-comparison-currency
   option has no conversion date, confirm the option is excluded from every
   calculation and share/export flow. Opening it must clear the placeholder
   conversion source; a real source and date are both required before the option
   or an editable backup can re-enter the supported comparison flow. While it is
   unrepaired, destructive clear, replacement, field removal, and option removal
   confirmations must disable the misleading backup action and explicitly say
   that continuing will proceed without a reusable backup.
