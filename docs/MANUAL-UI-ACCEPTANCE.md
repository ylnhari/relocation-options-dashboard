# Manual UI acceptance

Use only fictional figures. This checklist proves that the UI and agent path
produce the same canonical v5 editable document, and that a complete comparison
can be created, reviewed, exported, cleared, and restored without editing JSON.

## Editable coverage

| Area | User-created or editable through the UI |
| --- | --- |
| Comparison | Title, home/comparison currency, number format, income growth, expense inflation, projection years, and which saved plan is the current position |
| Monthly fields | Label, description, category, whether the amount is entered once for every plan or separately, amount, accuracy status, date, source, and note |
| Current position and possible plans | Name, location, income summary, country badge, household earners, plan currency, conversion ratio/date/source, gross compensation and its evidence, colour |
| Each plan's monthly inputs | Amount in either linked currency plus accuracy status, date, source, and note for every plan-specific field |
| Qualitative inputs | Spouse-income, childcare, transport, residence/visa, and bonus assumptions; benefits and uncertainties |
| Context and research | Excluded support name/amount/note; research topic, title, finding, scope, status, publisher, source title/link/date, and review note |

`kind`, schema version, stable IDs, `currentScenarioId`, and `updatedAt` are generated by the app.
Migration notes are read-only provenance created only when an older supported
file is converted; only the exact system-generated legacy notes are valid.
They are not a user assumption or financial input.

## Fresh setup

1. Open a clean browser origin and choose **Enter my details**. Confirm there
   are no saved plans, research records, support entries, sources, or qualitative
   claims. The standard field definitions and neutral `unknown` evidence shells
   are structure, not user data.
2. Add the current position first. Confirm the exported document identifies that saved place, job, or plan as the current position. Add a possible plan, select it as the current position, and confirm the reference changes without changing either plan's financial values. Remove the selected plan and confirm the app requires a remaining saved plan to be selected before the comparison can be saved.
3. Set the home/comparison currency, number format, income growth, expense inflation,
   and projection length yourself. Confirm these assumptions appear in the
   editable export and are not represented as agent-supplied or derived values.
4. Add, rename, and remove one field in each available category: deduction,
   automatic investment, living cost, commitment, and planned investment.
   Confirm recurring obligations and planned investments entered once for every
   plan ask for amounts in the home/comparison currency once, while every
   plan-specific field appears in every plan's value and evidence maps. Confirm every such amount starts blank
   and requires a typed value or the section's explicit **Use 0** action.
5. Enter an amount that applies to every plan and confirm the home/comparison currency locks before any
   plan exists. Set every such amount and excluded-support amount back to zero and
   confirm it unlocks; no entered number may silently change currency.
   Open the restart prompt while an unsaved fictional amount is present, cancel,
   and confirm the same draft value returns. Repeat and download the draft backup
   before cancelling.
6. Expand **External Help / Family Support received**, add a fictional context
   note, and confirm the UI says it is excluded from every total.
7. Expand **Research and sources**, add a fictional official HTTPS source and
   user-authored finding, date, status, and scope. Choose which plans it
   applies to.

## Current position, possible plan, and currency entry

1. Add a current position using the home/comparison currency. Confirm each amount has one input
   labelled as both the plan and home/comparison currency, and its conversion ratio
   is exactly `1`. Confirm gross and every plan-specific monthly amount start blank;
   saving is blocked until each has an entered amount, an explicit `0`, or the
   section's **Use 0** confirmation.
2. Add a fictional possible plan using another currency. Enter its currency, a
   strictly positive conversion ratio, a source, and an as-of date yourself.
   Confirm each is present in the editable export.
3. Enter gross pay in the `CAD` input and confirm the linked `USD` input changes.
4. Enter housing in the `USD` input and confirm the linked `CAD` input changes.
5. Repeat with a deduction, automatic investment, and any custom plan-specific
   commitment or planned investment.
6. Change the conversion ratio. Confirm stored local amounts do not move, linked
   home/comparison-currency amounts and calculated totals do, and amounts
   entered once for every plan remain fixed.
7. Save, reopen the plan, and confirm the linked inputs, preview, card, expanded
   calculation, and comparison table agree.
8. Attempt to save an otherwise complete foreign-currency plan without
   each of currency, positive ratio, date, and source. Confirm the plan is
   rejected as one invalid unit; no partial plan is added or exported. Repeat
   after removing one linked plan-specific value and one linked evidence entry.

## Progressive disclosure and validation

1. Confirm a long category such as standard living costs is collapsed initially
   and its summary shows the item count and entered total.
2. Confirm short required categories remain open.
3. Use Tab, Enter, and Space on every disclosure summary. Focus must be visible.
4. Clear a required value inside a collapsed section and submit. The section must
   open, the error summary must be announced, and focus must move to the field.
5. At widths of `320px` and `650px`, confirm linked currency inputs stack without
   horizontal page overflow and Save/Cancel remain reachable.

## Keyboard, motion, and visual accessibility release gate

1. With only the keyboard, open **Download or import**, verify Tab and Shift+Tab
   stay within the dialog, then press Escape and confirm focus returns to its
   opener. Tab to an ordinary button and a disclosure summary: each must show a
   clearly visible focus indicator. Use Enter and Space to open and close native
   disclosure summaries.
2. At `320px`, add a fictional research finding containing a long unbroken token
   and confirm it wraps or breaks without horizontal page overflow. At `1440px`,
   confirm the monthly comparison remains two columns with no root overflow.
3. With reduced motion enabled in the operating system or browser, confirm motion
   is effectively removed (computed animation and transition durations are
   `0.01s` or less) and navigation does not smooth-scroll.
4. At both 100% and 200% zoom, manually sample the *composited* foreground and
   background actually rendered for normal, muted, and error text, plus focus,
   active-control, and error-state indicators. Require at least 4.5:1 for text
   and 3:1 for non-text indicators; repeat after opening a modal and after an
   error.

## Full round trip

1. Add user-authored qualitative assumptions, benefits, uncertainties,
   field-level evidence, and at least one source through the UI.
2. Confirm External Help / Family Support is visible as context on the dashboard
   but does not alter income, expenses, savings, charts, or rankings.
3. Download the editable comparison file and the family view. Validate the
   editable file with `npm run validate:data -- <file>`.
4. Normalize the editable v5 JSON by parsing it, replacing only `updatedAt` with
   one fixed token, and serializing object keys in a deterministic order. Keep
   every other field, including title, locale, field definitions, values,
   evidence, conversion details, assumptions, support, research, qualitative
   fields, and migration notes. Do not add calculated totals or projections.
5. Clear only this fictional browser dashboard, import the editable file, review
   the complete-replacement preview, and confirm it. Export again, normalize it
   the same way, and confirm exact equality with the pre-clear normalized file.
6. Confirm all inputs and totals before and after. Invalid imports, including a
   document with one plan missing a linked field or a
   foreign-currency conversion component, must leave the existing
   dashboard unchanged.
7. Start removal of a populated field and of a plan. Each confirmation must
   name the scope and offer a saved backup, Cancel, and a distinct final removal
   action. Cancel both operations and confirm nothing changed.
8. With a recognized older browser migration, confirm the gross-to-net
   difference and aggregate living amount appear only in clearly labelled
   **Legacy ... (review required)** fields. They must not appear as an income
   tax or leisure claim. Confirm that empty legacy qualitative details remain
   empty rather than becoming a generated narrative, and that unknown migrated
   financial inputs do not display a fabricated source.
9. With a recognized older browser migration whose non-comparison-currency
   plan has no conversion date, confirm the plan is excluded from every
   calculation and share/export flow. Its legacy ratio and placeholder must not
   count as a current conversion rate or source. Opening it must replace the
   placeholder with a real ratio, source, and date before the plan or an
   editable backup can re-enter the supported comparison flow. While it is
   unrepaired, destructive clear, replacement, field removal, and plan removal
   confirmations must disable the misleading backup action and explicitly say
   that continuing will proceed without a reusable backup.
